# report.md — база знаний (факты и грабли)

## Факты кода

- В коммиты не попадают комментарии и TODO-маркеры (пользователь зачищает). Код пишется чистым, без комментариев.
- Стуб метода с типом возврата: `throw new Error("Not implemented")` — это код, не комментарий; в коммит попадает.
- Коммиты делает пользователь; координатор только готовит файлы и верифицирует.

## Структура

```
src/
  entry.ts                     — DI-композиция, точка входа (4-space, явные типы у локальных констант)
  objects/                     — доменные объекты и типы данных
    abstract.ts                — интерфейсы: ITickable, IEffect, IItemInstance
    data.ts                    — Vec2, EffectData, PlayerData, WorldSnapshot (declare class — ТОЛЬКО типы)
    GroundItem.ts              — GroundItem (declare class — только тип)
    World.ts                   — World: tick, players, ground items, snapshot
    Player.ts                  — Player: position/target/hp/armor/effects/inventory, движение к target
    Inventory.ts               — Inventory: стэкинг инстансов
    ActiveEffect.ts            — ActiveEffect: remainingTicks, tick() → boolean
    items/                     — IItem.ts + Medkit/Armor/Bandage/Flare
  infrastructure/
    GameFactory.ts             — stateless-фабрика
    GameServer.ts              — HTTP-статика (3000) + WS (3001), Observer-подписка на gameLoop
    services/                  — StaticDataService, ItemRegistryService, GameLoopService, ValidationService, DemoService
    storage/                   — IStorage, MemoryStorage
  services/                    — доменные сервисы: EffectService, FlareService, GroundItemService, InventoryService
  utils/                       — distance.ts (sqrDistance), validation.ts
  test/                        — runner.ts + scenarios/ (smoke, drop-pickup, ground-timeout, use-effect, concurrent-pickup)
public/
  index.html + app.js          — canvas-фронтенд
```

- Глобальных переменных нет. Код в глобальном контексте — только `src/entry.ts` (композиция) и `src/test/runner.ts` (тестовый entry). Свободные метод-декларации — только в слое `src/utils/`.
- Типы данных: `objects/abstract.ts` — интерфейсы `ITickable {tick(): boolean}`, `IEffect {type, remainingTicks, data?}`, `IItemInstance {id, type, amount, stackable}` (readonly-поля). `objects/data.ts` — `Vec2`, `EffectData`, `PlayerData`, `WorldSnapshot` объявлены `declare class` — **ambient-типы без runtime-кода** (объекты создаются литералами; конструкторов НЕТ). `objects/GroundItem.ts` — `GroundItem {id, type, position, expiresAtTick}` (тоже `declare class`). `WorldSnapshot {tick, players: PlayerData[], groundItems: GroundItem[], inventories: Record<string, IItemInstance[]>}`.
- `StaticDataService` (`infrastructure/services/`) — единственный владелец config: `readonly config = {...} as const` (типа `Config` нет — config передаётся как `any`; решение пользователя). `config` содержит: `GROUND_LIFETIME_TICKS: 600`, `TICK_INTERVAL_MS: 100`, `WORLD_WIDTH: 800`, `WORLD_HEIGHT: 600`, `STORAGE_DELAY_MS: 50`, `HTTP_PORT: 3000`, `WS_PORT: 3001`, `PLAYER {pickupRadius: 50, speed: 10, maxHP: 100, maxArmor: 100, spawnHP: 50, spawnArmor: 50}`, `ITEMS {medkit, armor, bandage, flare}`.

## Правила конструкторов (зафиксировано пользователем)

- Конструктор только получает и хранит ссылки на нужные сервисы (DI). Создание объектов в конструкторе — запрещено. Исключение (решение пользователя): из config-числа инициализировать `private readonly` поле в ctor (`GameLoopService._tickIntervalMs`, `MemoryStorage._delayMs`).
- Создание/инициализация — отдельными методами (паттерн `initialize()`). Пример: `GameLoopService.initialize(world)` принимает готовый мир (создан entry через фабрику); публичных полей, инициализированных в ctor, нет.
- Фабрика stateless: `World` не держит, «уже создан»-проверок нет. Фабрика регистрирует созданные сущности в `gameLoop` (`register`).
- Владелец `World` — `GameLoopService`: хранит мир, полученный в `initialize(world)`, exposes только readonly-геттер `world`. Сервисы `World` в ctor не получают и НЕ кэшируют — читают `gameLoop.world` в методах.

## Pitfalls & dead ends

- TDZ-замыкание в ctor `GameLoopService` (было: колбэк `(snapshot) => server.broadcast(snapshot)`, где `server` создаётся позже) — формально работало только потому, что колбэк не вызывался до присваивания `server`; любой рефактор (синхронный первый тик, `initialize` до создания `server`) → `ReferenceError: Cannot access 'server' before initialization`; плюс ESLint `no-use-before-define` и невозможность подменить `server` в тестах. ИСПРАВЛЕНО Observer'ом: `GameLoopService.onSnapshot(listener)` + `GameServer` подписывается в собственном ctor (`this._gameLoop.onSnapshot((snapshot) => this.broadcast(snapshot))`) — gameLoop не знает про сервер, зависимый цикл `loop → server` убран.
- Держание `World` как АРГУМЕНТА ctor или как поля сервиса/фабрики (например `GameFactory.world`) — нарушение «ctor = только ссылки на сервисы» и stateless-фабрики; мир хранит `GameLoopService` (получает в `initialize(world)`).
- `declare class` в `objects/data.ts` и `objects/GroundItem.ts` — ambient-типы БЕЗ runtime-кода: `Vec2`/`PlayerData`/`WorldSnapshot`/`GroundItem` не инстанцируются через `new`, объекты создаются литералами; не искать конструкторы.
- `Player.addEffect` ЗАМЕНЯЕТ эффект того же `type` (не дублирует) — повторный use bandage/flare перезаписывает оставшиеся тики, а не складывает.
- Хранилище `World._groundItems` — Map, но `getGroundItemById` читает через O(n) `find` по массиву (влияния нет — ground items на карте мало).
- `ItemRegistryService.get(type)` КИДАЕТ на неизвестном type (`Unknown item type: ...`), а НЕ возвращает `undefined` — в `ValidationService.validateUse`/`validateDrop` неизвестный type → hard-throw, а не soft `{ok:false}`. Если unknown type нужен как business-failure → `{ok:false}`, нужно не-кидающее чтение (например `getAll().find(...)`).
- Циклическая зависимость `GameLoopService` ↔ `GameFactory` устранена: фабрика НЕ в ctor `GameLoopService`; `GameLoopService.initialize(world)` принимает готовый мир; фабрика получает `gameLoop` в ctor (DI: gameLoop → factory).
- Циклическая зависимость `GameLoopService` ↔ `EffectService`/`GroundItemService` устранена: сервисы получают `GameLoopService` в ctor и сами регистрируются в `initialize()`; `GameLoopService` НЕ знает о них.
- `Player.tick()` НЕ тикает эффекты (они тикаются `GameLoopService` напрямую) — иначе double-tick. `Player.tick()` = `advanceEffects()` (cleanup) + `moveTowardTarget()` (движение к `_target`).
- `ActiveEffect` ctor валидирует `remainingTicks < 0` (non-negative, НЕ `<= 0`). Метода `clone()` больше НЕТ (удалён из `IEffect` и `ActiveEffect`). Эффект тикает только `GameLoopService`, при достижении 0 возвращает `false` и выносится из цикла — НИКОГДА не уходит в минус.
- `PlayerData.effects: EffectData[]` (чистый data-тип `{type, remainingTicks, data?}`, `objects/data.ts`); `Player.toData()` мапит живые эффекты → plain-объекты `EffectData`. Раньше живой `ActiveEffect` сериализовался в JSON как приватное `_remainingTicks`, а публичный геттер `remainingTicks` (на прототипе) в JSON НЕ попадал — по сети шло `_remainingTicks` (клиент читал `undefined`).
- Порядок тика: игроки регистрируются раньше эффектов → `Player.tick()` (cleanup) идёт ДО `ActiveEffect.tick()` (декремент) в одном проходе `GameLoopService.tick()` → эффект с N тиков живёт N+1 тиков (test `use-effect` закладывает `healPerTick * (duration + 1)`).
- Демо-подбор НЕ проходит `ValidationService`: `DemoService` сам поллит дохождение (`sqrDistance <= pickupRadius^2`) и зовёт `inventoryService.pickup` напрямую. WS-команды как раньше идут через `validate*`.
- Конкурентный подбор в демо: `Promise.allSettled([pickup(p1), pickup(p2)])` — loser получает «Ground item not found» (item синхронно удаляется в sync-префиксе winner'а, до первого await). В single-thread JS winner детерминирован — первый вызов (p1).
- Демо больше НЕ ждёт таймаута ground item (раньше ≈65с на ожидании medkit, теперь несколько секунд): `runScenario` — спавн → подход → pickup → drop/use → mid-drop → race → конец.
- Canvas растягивается флексом под размер окна (viewport 1200×800 → canvas 1066×800 при внутреннем 800×600) — координаты клика масштабируются: `x = (e.clientX - rect.left) * (canvas.width / rect.width)`, аналогично `y` (иначе клик «не в ту точку», выбор игрока «в случайном месте»).
- `PLAYER.speed: 10` (было 2) — по требованию пользователя (движение слишком медленное). Тесты от скорости не зависят.
- Эффект flare живёт всего 30 тиков (3с) — проверка «есть ли подсветка» через снапшот/пиксели ДОЛЖНА быть синхронной с drop или в пределах ~3с, иначе эффект уже спал и проверишь пустоту (дважды наступил: и с пикселями canvas, и с WS-самплингом).
- `tsx` под песочницей workspace-write: `spawn EPERM` — esbuild запускает дочерний процесс, а kernel-ограждение Windows блокирует grandchild-spawn (структурно; правила dsh-allow это не снимают — они компилируются в профиль только на macOS/Seatbelt). Тесты через tsx под workspace-write не запускать.
- Верификация без дочерних процессов (это `verify.bat`): `tsc --noEmit` → `tsc` (сборка в `dist/`) → `node dist\test\runner.js`. Smoke — in-process (в коде нет `child_process`) — проходит полностью под workspace-write.
- dsh-allow: правило `E:\dev` (все 5 возможностей, recursive) добавлено пользователем 2026-10-19 в `C:\Users\USER\.dsh\dsh-allow.json` — покрывает pre-execute gate, но не kernel-ограждение Windows.
- Стен-клок между ходами сессии может быть на порядки длиннее, чем кажется (сервер, запущенный «пару минут назад», жил ≈3.4ч → tick ≈ 114k). Временныe рассуждения строить по `world.tick` (10 тиков/с) и timestamp'ам логов/файлов, не по ощущению «сколько минут прошло».
